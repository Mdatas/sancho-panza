# AoE2 Coach — review of 2026-10-18 (v0.11.1)

Scope: (1) how the coach separates meta / anti-meta / meme advice, (2) security and privacy of the app and of a GitHub release, (3) integrity of the AoE2 knowledge base (builds, patches, cross-source contradictions), (4) critical analysis and roadmap. Everything marked **done** shipped in v0.11.1; everything else is a recommendation.

---

## 1. Meta vs anti-meta vs meme

**Problem.** v0.11.0 added ~365 Poop Lord strategies and 24 "Break the Meta" games under a single "meme" label. Two things were wrong: (a) a real anti-meta plan (Armenian Feudal long swords at 17xx ELO, 12-minute knights, Bohemian Hussite-wagon rush) was labelled the same as trolling (8-pop scouts, "hide in the corner"), and (b) nothing told the coach to *say* which one it was giving.

**Done.**
- Three tiers, defined in `data/knowledge/meta_antimeta_meme.md` and enforced in the system prompt (`src/main/brain/prompt.js`, rule "META vs ANTI-META vs MEME"): META = the standard plan at the player's level; ANTI-META = a real non-standard plan that works under stated conditions; MEME = cheese for fun or one-time surprise. The coach must name the tier whenever it is not META, decide it from the note's own "realistic use / ELO" lines (never from the title), answer "best opening / how to climb" with META only, and never present a meme as meta.
- File labels now carry the tier: `Break the Meta (anti-meta)`, `Poop Lord (meme)` for Book of Memes / Ultimate Meme Guide / 5 Fun Memes / Slow and Clean, `Poop Lord (anti-meta/meme)` for "every unique strategy" and New 2025/2026 (a mix; the note says which), `Poop Lord (casteo)` for Legend of the game.
- Retrieval (`src/main/engine/knowledge.js`): every section has a tier from its file; meme sections score ×0.6 and anti-meta ×0.8 unless the question asks for a meme, cheese, surprise, fun strat, or how to stop one. Each hit now returns `tier`.

**Still to do.** Per-note tiering: the mixed files ("every unique strategy", New 2025/2026) are tiered at file level. A pass that tags each note META/ANTI-META/MEME from its own text (ELO reached, "works at high elo", "troll") would let the ranking work per note. It should be done by reading, not by keyword guessing.

## 2. Security and privacy

### 2.1 What the app actually does with data

| Flow | Where it goes | Notes |
|---|---|---|
| Your question, match state, retrieved notes | `api.anthropic.com` (default) or the OpenAI-compatible Base URL you configure | Only outbound call with your content. No server of ours, no telemetry. |
| API keys | `%APPDATA%\AoE2 Coach\settings.json`, encrypted with Windows DPAPI via Electron `safeStorage` (`enc:` prefix) | Decrypted only in the main process; the renderer receives it to fill the settings field (see S3). |
| Conversation log | `%APPDATA%\AoE2 Coach\logs\coach-YYYY-MM-DD.jsonl` | Every question, tool call, answer, model, cost. Plain text, no retention limit (S5). |
| Voice output | Microsoft Edge neural TTS endpoint (package `msedge-tts`) | The *answer text* is sent to Microsoft. SAPI fallback is fully local (S6). |
| Game data / build orders | `raw.githubusercontent.com/SiegeEngineers/aoe2techtree`, `api.github.com/.../CraftySalamander/rtsbuilds` | Downloaded on launch, parsed as JSON only, validated before saving (S7). |
| Installer | `github.com/electron/electron/releases` | Official Electron runtime; now hash-checked (S2). |

Nothing listens on a port, there is no remote control, no auto-updater, no MCP server, no screen capture. The app reads nothing from the game: you type the situation.

### 2.2 Findings

| # | Severity | Finding | Status |
|---|---|---|---|
| S1 | Medium | Renderer windows ran with `sandbox: false`. Both windows load only local files behind a strict CSP (`default-src 'self'`, no `connect-src` to the outside, no `unsafe-inline` scripts), `contextIsolation: true`, `nodeIntegration: false`, and the preload only exposes `ipcRenderer.invoke` wrappers, so this was defence in depth, not an open hole. | **Done:** `sandbox: true` on both windows; smoke test passes. |
| S2 | Medium | `setup.ps1` downloaded the Electron zip over HTTPS with no integrity check. | **Done:** the installer downloads `SHASUMS256.txt` from the same release, compares SHA-256 and deletes a mismatching zip. |
| S3 | Low | `settings:get` returns the decrypted API key to the renderer so the settings field can show it. With CSP + sandbox + every dynamic string escaped (`esc()` / `md()`), a renderer compromise is unlikely; the only exfiltration path would be `openExternal` with the key in a URL. | Open. Recommended: return a masked value (`•••• last4`) plus a "set" flag and only send a new key when the user types one. |
| S4 | Low–Medium (user-dependent) | The OpenAI-compatible provider sends the key as `Authorization: Bearer` to whatever Base URL is typed, including plain `http://` (needed for Ollama/Tailscale). A typo or a malicious URL leaks the key. | Open. Recommended: warn (red text) when the URL is neither `localhost`/`127.0.0.1` nor `https://`, and show the host in the "Probar conexión" result. |
| S5 | Privacy | Logs keep every question and answer forever in plain text; `settings.json` also stores the last match state. Fine for one person on their own PC; a shared PC exposes play history. | Open. Recommended: 30-day retention (delete older `coach-*.jsonl` on launch), a "borrar logs" button, and a line in LEEME. |
| S6 | Privacy | Edge TTS sends the answer text to Microsoft through an undocumented endpoint (no account). | Open. Already configurable (`ttsEngine: edge | sapi | off`); document it in LEEME and label the setting "envía el texto a Microsoft". |
| S7 | Low | Sync wrote `rtsbuilds` files under the name returned by the GitHub API without stripping path separators. GitHub never returns slashes in `name`, but it costs nothing to be safe. | **Done:** `path.basename(e.name)`. |
| S8 | Info | Global hotkeys F6–F10 are captured system-wide while the app runs (by design). | Documented in LEEME; keys are configurable. |
| S9 | Info | SAPI fallback spawns `powershell.exe`; the text goes through stdin (not interpolated) and the output path is escaped. `Instalar.bat` uses `-ExecutionPolicy Bypass` (standard for an unsigned script). The installed exe is `electron.exe` renamed, unsigned: SmartScreen and some antivirus heuristics will warn. | Open: code-signing certificate, or ship the electron-builder NSIS installer signed. |
| S10 | Info | No auto-update, so no remote code path, but also no security updates without a reinstall. | Acceptable for now; if you add updates, use electron-updater with signed releases only. |
| S11 | Info | Dependencies: Electron 44.7.2, `msedge-tts`, electron-builder. Run `npm audit` before each release; pin versions (they are pinned in `package-lock.json`). | Routine. |

**Remote access, for anyone involved.** The app gives no remote access to the player's PC, to you, or to me. During this session the work ran in a cloud container; the only thing touched on your machine was your Chrome, through the extension, to read YouTube transcripts and playlists (tabs closed afterwards). The release zips were scanned: they contain no API key (only the `sk-ant-…` placeholder in the settings field).

### 2.3 If you publish on GitHub

- **Done:** `.gitignore` (node_modules, dist, logs, settings.json, `.env`, `*.key`). The project has no git history yet, so nothing can leak from old commits. A scan of the source tree found no email, name, key or absolute home path.
- `package.json` declares `"license": "MIT"` but there is no `LICENSE` file. Add one (or change the field) — your call.
- **Content provenance.** `data/knowledge` is Spanish summaries of third-party material, each section with its source URL: videos by Hera, Spirit Of The Law, TaToH, El Biry, Poop Lord, Resonance22, aoe2matchup; pages from aoecoach.com, the fan wiki, ageofnotes/aoe2insights stats. Summaries with attribution are the normal case; the `aoecoach_web.md` sections are the closest to the original text, so either paraphrase them further or ask the site. Add a `CREDITS.md` naming every source and the upstream licenses of `SiegeEngineers/aoe2techtree` (game data) and `CraftySalamander/rtsbuilds` (build orders) — check both licenses before publishing; the README already names them.
- The icon in `build/icon.png` must be your own artwork, not a game asset. "Age of Empires" is a Microsoft trademark: keep "AoE2 Coach" as a fan project and say so in the README.
- `installer/LEEME.txt` and README still say "mandale la captura a Claude" and "v0.2 … no live match reading yet"; rewrite the README header for strangers (what it is, that it is key-free and the user brings their own key).
- Never commit `%APPDATA%\AoE2 Coach` contents; the smoke test's `--shot` screenshots go to a path you pass, keep them out of the repo.

## 3. Knowledge-base integrity

### 3.1 Method
`tools/audit_kb.py` (new, deterministic, re-run after every patch or import) checks: section sizes vs the 1800-character search window, duplicate titles, the patch history (order, duplicates, every build number cited in a note exists, month agreement between a note's "Update N (date)" and the history), "parche actual" claims, future dates, VIGENCIA coverage and tagging, a list of known cross-source hot spots, civ-name spelling variants, every bundled build order (JSON validity, resource split vs villager count, units/techs the civ cannot get in the current tech tree), and mentions of removed techs outside dated notes. Ground truth for "today" is `data/game` (aoe2techtree snapshot of patch 185872), never a video.

`test/knowledge.test.js` (new, runs in `npm test`) keeps the cheap invariants green: no searchable section over 1800 chars, no duplicate titles, one "current patch", patch history in order and ending at it, all bundled builds valid, aliases/tiers/diversity behave.

### 3.2 Numbers (after the fixes)
- 224 markdown files; 3,047 raw sections; 2,704 searchable sections after automatic splitting (the app now splits long sections at load, so no note loses its tail in retrieval — previously 22 top-level sections were truncated, including the aoe2matchup intro and the 185872 civ-balance list).
- Patch history: 62 entries, 2019-11-14 → 2026-09-22, in order, no duplicates. Notes cite 61 distinct build numbers; 60 exist in the history; the one missing (179158) is a hotfix mentioned on the 177723 page. 0 month disagreements between notes and history. All "parche actual" claims = 185872.
- VIGENCIA: 2,234 dated sections; 10,527 VIGENCIA bullets; 459 marked SIN VERIFICAR (honest unknowns); **6,955 bullets (66%) carry no type tag** (CAMBIÓ / SIGUE IGUAL / SIN VERIFICAR / IMPACTO). The coach reads the text anyway, but tag discipline varied by batch (SotL and Poop Lord batches are the loosest).
- Build orders: 41 bundled `rtsbuilds` builds. **None has a date or patch field** (format limitation), so the panel cannot warn about staleness. **20 steps in 9 builds** have a resource split that does not add up to the villager count (upstream data quality: `archers20pop1range`, `boharena25popcastledrop`, `cum2tc18pop`, `eth2range`, `jap18popmanatarms`, `khm23popknightsrush`, `mayarchersopening`, …). **1 build references something the civ cannot build:** `geo19popfastknights` (Georgians) uses a Lumber Camp; Georgians have Mule Carts.

### 3.4 Still open (data)
- Patch history gaps that the VIGENCIA blocks could not date ("el historial no lo fecha"): Supplies removal build, Georgian regeneration steps, Gbeto 40 HP, Hindustani stable armour, Portuguese shared-vision removal, Sicilian transport -50%, Vikings' lost Gambesons. Each is written as SIN VERIFICAR, which is the right behaviour, but a pass over the official notes for 2023–2025 would close most of them.
- The `aoecoach.com` figures that disagree with the official 169123 notes (Siege Tower HP, Fire Lancer, Fortified Church, Flemish Militia, Longboat, Turtle Ship) are kept as the site states them with a warning; the coach should quote `parches_recientes` for numbers, not that file.
- 31 videos had no captions and have no note (SotL 11, Break the Meta 2, every unique strategy 2 so far, …; the lists are in the `_sin_subtitulos.txt` files of each batch).
- "every unique strategy": 226 of 404 videos processed; the remaining batches resume when the API budget resets. "Legend of the game": 12 of 27.

### 3.5 How the errors got in (process)
- ~35 parallel agents wrote notes against a patch history that is itself a summary; when the history lacked a change, some agents attributed it to a plausible build (Supplies → 141935) instead of marking it unknown. Rule added to the briefs for next time: "if the history does not have it, write SIN VERIFICAR, never pick a build".
- Tag discipline (CAMBIÓ / SIGUE IGUAL …) was in the brief but not enforced; the audit now counts untagged bullets.
- Thin auto-captions (Poop Lord, El Biry live games) produced partial build orders; the agents said so in the note rather than filling numbers — keep that rule.

## 4. Critical analysis and roadmap

### 4.1 Inconsistencies in the product today
- README header still says "v0.2 … no live match reading yet" and "41 builds"; LEEME tells users to send screenshots "a Claude". Rewrite both for a public audience.
- `package.json` says MIT, no LICENSE file. `setup.ps1` comments mention "whisper" files that are not shipped (there is no speech input; README says so correctly).
- Language: most notes are Spanish, but `estrategias_jugadores`, `parches_recientes`, `wiki_estrategia_extracto`, `meta_y_tips_parche185872`, `stats_*` are English. The coach copes, but search tokens differ; the new alias groups cover civ/unit names only. New files should be Spanish with English names in parentheses, like the rest.
- `data:info` "notes" count now counts split chunks (2,704), not notes; label it "fragmentos".
- Two tiers of "truth" coexist: `civs/*.md` profiles (derived from data, served whole by `civ_info`) and video notes (dated). The prompt says data wins; make the UI show it too (a "datos del parche 185872" stamp next to every quoted number would help trust).

### 4.2 Architecture and cost
- **Prompt cache never hits.** `buildSystemPrompt` embeds the per-question notes (`keyData`) inside the system block that carries `cache_control`, so the cached prefix changes every question. Split the system prompt into a static block (rules, tool guidance — cached) and a dynamic block (state + notes — uncached, or moved into the user turn). With ~12–20k characters of notes per question this is the single biggest cost lever; the logs already record `usage` to measure the before/after.
- Retrieval is keyword overlap over 2.7k chunks with a query built from question + state. It works for named entities (civ, unit, map) and fails on paraphrase ("se me cae la eco en castillos"). Next step: BM25 with title/civ-tag fields, then a local embedding model (multilingual, via transformers.js or onnxruntime) for hybrid ranking; keep the deterministic VIGENCIA pairing.
- VIGENCIA is a snapshot dated 2026-10-18 against 185872. It rots at the next patch. Build the **patch-bump routine**: (1) sync `data/game`, (2) diff units/techs/civ bonuses old vs new, (3) list the notes that mention anything changed, (4) append the official notes to `parches_historial`, (5) re-run `tools/audit_kb.py` and `npm test`, (6) show a banner in the app when the data commit is newer than the knowledge revision date.
- Build orders: add `patch`/`date` to imported builds (ask on import, default today), check each step against the civ tree at load (the Georgians/Lumber Camp case) and show a small warning in the panel; consider sending the 20 arithmetic fixes upstream to rtsbuilds.
- Renderer: `app.js` is one 35 KB file with globals and no tests beyond the smoke run. Add unit tests for `md()`/`esc()` (XSS regressions), the slash-command parser and the settings migration; split the file by panel.

### 4.3 Easier to use
- First-run flow: today the user must find Ajustes → Cerebro → key → Probar. Make the first launch a 3-step card: paste key → test → "decime tu civ y la del rival" with civ pickers, then one sample question.
- Buttons for the three facts the coach needs (mi civ / rival / mapa / edad) in the compact bar, not only slash commands; keep the commands for power users.
- One-click "qué cambió en este parche para mi civ" (the data is in `parches_recientes` + the civ profile) and "qué me puede hacer el rival" (opponent profile + counters) — both are already tool calls, expose them as buttons.
- Auto-detect the match instead of typing it: read the player's last/current game from aoe2insights or aoe2companion (public profile id → civs, map, ELO) or parse the recorded-game file the game writes; this removes most of the typing and is the biggest usability jump available.
- Team games: state has one opponent civ; add allies/opponents lists and a "pocket/flank" role so the Slow-and-Clean and team notes become useful.
- Voice: input is text only; a push-to-talk with local Whisper (the installer comment suggests it was planned) would fit the in-game use. Until then, say clearly in the UI that F10 is typing.
- Show the tier in the UI: a small META / ANTI-META / MEME chip on the answer when the coach used an off-meta note, and the note's date — so the player sees why the advice is unusual.
- A "fuentes" line under each answer (titles of the notes used, with their dates) makes the dated-advice rule visible and lets the player judge.

### 4.4 Suggested order
1. Prompt-cache split (cost) and the masked key / URL warning (S3, S4) — small, high value.
2. Patch-bump routine + banner; close the dated gaps in `parches_historial` from the official notes.
3. Per-note tiering of the mixed Poop Lord files; tier chip + sources line in the UI.
4. Build-order checks against the civ tree and `patch` fields; onboarding card; civ/opponent/map buttons.
5. Match auto-detection (aoe2insights/companion or recorded games); team-game state.
6. Hybrid retrieval (BM25 → embeddings); renderer tests and split.
7. Code signing or NSIS installer; CREDITS.md and LICENSE before the GitHub release.
